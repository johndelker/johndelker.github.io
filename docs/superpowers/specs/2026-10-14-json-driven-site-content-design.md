# JSON-Driven Personal Site Content and View Navigation

## Goal

Make the personal website's content straightforward to edit without changing its markup, and make its navigation switch visible views instead of scrolling to page anchors. The Home view presents John Delker's photo and brief introduction.

## Scope

- Refactor the main academic website in `index.html`.
- Add a `content.json` file containing the site's editable copy and image paths.
- Add lightweight JavaScript to load the JSON, render content, and switch views.
- Update the README's main-site description and preview/content-editing instructions.
- Keep navigation labels/buttons and contact/social buttons in HTML.
- Leave the attendance tool and its Google Apps Script backend unchanged.

## Content model

`content.json` is the source of truth for page-authored text and image paths outside the navigation and contact controls. It includes the document title and description, Open Graph title and description, favicon URI, home title/subtitle/introduction/photo path and alt text, and each content view's title and blocks. Blocks support paragraphs, lists, and cards (with a heading and nested paragraph/list blocks). Inline text supports links, preserving existing links embedded in prose. The footer's displayed name is also stored in JSON; the current year remains generated by JavaScript.

The initial data preserves the existing Home, Research, Software & Tools, Teaching & Outreach, and Other content, including card headings. Existing image paths are represented as JSON values. Navigation labels and contact control labels, addresses, URLs, and icon paths remain in HTML by design.

## Navigation and rendering

The navigation buttons use stable view identifiers. Home is first and is selected initially. Selecting a navigation button hides the other views and displays the selected view without changing the URL fragment. The selected navigation control exposes its active state accessibly. Content is rendered from JSON using DOM APIs and text nodes; inline links are created as anchors from structured link data rather than injecting arbitrary HTML.

The content JSON is loaded with `fetch`, so local preview should use a static HTTP server. The initial HTML retains static title, description, Open Graph, and favicon fallbacks for crawlers that do not run JavaScript; these values mirror `content.json`. If loading or parsing fails, the page displays a clear content-loading error in the main content area and disables the view buttons.

## Acceptance checks

- Home is the leftmost navigation button and is visible on initial load.
- Selecting each navigation button displays only its corresponding view and does not scroll to an anchor.
- The existing copy, content links, and portrait are represented in `content.json` and appear in the rendered page.
- Navigation and contact controls remain HTML-authored.
- The page remains usable on narrow and wide viewports, and navigation state is exposed to assistive technology.
- The attendance pages and backend are not modified.
